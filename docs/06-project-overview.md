# 项目整体说明：企业知识问答 Agent

## 1. 要解决什么问题

员工询问制度或产品规则时，普通问答容易出现三类错误：没有找到原文就猜答案、看到两份相互矛盾的文件却擅自选一份、工具故障时仍输出看似确定的结论。本项目让 Agent 先找资料、再读原文，最后给出带文档 ID 和原文引句的回答；无法确定时明确说明缺口与任务状态。

这是笔试题目 3 的最小可运行实现。知识库是 10 份合成资料，不代表小影科技的真实制度；入口是 Python CLI，不需要前端或线上服务。

## 2. 核心思路与一次运行

```text
用户问题和可选对话历史
        ↓
模型选择一个动作：搜索资料 / 读取文档 / 提交结束提案
        ↓
程序校验工具名和参数，执行工具并校验实际返回
        ↓
工具结果作为 ToolMessage 交回模型
        ↺ 模型根据这次观察重新选择动作
        ↓
引用核验通过后输出回答；否则反馈错误供模型修正，或明确返回未完成状态
```

`src/knowledge_agent/agent.py` 用 LangGraph `StateGraph` 实现“模型决策”和“执行动作”两个节点。LangChain 定义 `search_documents`、`read_document` 和 `finish` 三个可供模型选择的工具。模型每轮只提交一个工具调用；程序负责校验、计数和路由，不根据题目关键词写死下一步。`finish` 是模型提出的结束动作，其中 `completed` 必须通过引用检查才会成为最终成功状态。

`src/knowledge_agent/knowledge_base.py` 从 `data/documents.json` 读取资料，以中文字双字片段和英文词做轻量检索。搜索仅返回候选段落、文档 ID、版本日期、适用范围和替代关系；模型需要再调用 `read_document` 获取原文。检索排序不裁决冲突，也不生成答案。资料少、任务以验证决策链路为主，因此暂未引入向量数据库。

`src/knowledge_agent/answer_validator.py` 检查 `completed` 的回答和引用：必须有回答和引文；引文文档须在本轮成功读取，段落 ID 要匹配，引句必须是原文的连续子串。冲突记录中的双方文档也必须读过。校验失败的具体原因作为工具观察反馈给模型，模型只能在剩余步数内修正。这是机械校验，不能代替人工判断“引文是否真的支持结论”。

## 3. 题目审核要点如何被验证

| 审核点 | 本项目的处理 | 可核对的运行材料 |
| --- | --- | --- |
| 有依据的正常回答 | 搜索后读取原文，引用通过校验才完成 | `examples/S01-input.json`、`S01-output.json`、`S01-trace.jsonl` |
| 文档冲突 | 读取 D01 与 D02；两者无明确优先级或替代关系时，列出冲突并请求确认 | `examples/S02-*` |
| 资料缺失 | 改写检索仍无资料时，返回 `insufficient_evidence`，不编造答案 | `examples/S03-*`、`S18-*` |
| 改写问题和上下文追问 | 重新检索并核对当前适用范围，不直接沿用旧答案 | `examples/S04-*`、`S05-*` |
| 工具故障 | 工具返回明确错误，模型观察后可调整或以 `failed` 结束 | `examples/S06-*` |
| 观察改变下一步动作 | 首次搜索被受控置为空后，真实模型换检索词，再读取资料 | `examples/S09-*` |
| 步数和工具次数上限 | 达到上限返回 `limit_reached`，保留已执行步骤，不伪装完成 | `examples/S07-*`、`S08-*` |
| 版本与适用范围 | 只依据明确的替代关系裁决版本；身份不明时先澄清 | `examples/S12-*`、`S13-*`、`S20-*` |

S06 和 S09 是**真实模型加受控工具结果**：模型的后续动作是真实生成的，故障和首轮空结果是示例运行器注入的。它们证明模型会消费不同观察，不证明真实工具的故障率或检索召回率。`tests/` 中的模型测试替身只验证程序流程，也不被当作真实模型效果证据。

每份 Trace 记录运行 ID、时间、模型动作及参数、实际工具结果、执行状态和下一动作。Trace 不包含模型内部思维或 API Key。评审可以逐步比对工具返回与下一轮模型动作，而不必只相信最后一段回答。

## 4. 可靠性边界

- `max_steps` 限制模型决策次数，`max_tool_calls` 限制搜索和读取次数；LangGraph 递归限制提供额外保险。
- 无效输入返回 `invalid_input`；模型或工具异常、非法动作及无法保存 Trace 等情况不会返回成功。
- `needs_clarification`、`insufficient_evidence`、`failed`、`limit_reached` 与 `completed` 分开表示，便于区分“缺资料”“规则不明确”“系统出错”和“执行额度耗尽”。
- 模型客户端关闭隐式自动重试。检索词是否调整、是否继续读取、是否结束由模型根据收到的结果决定。

## 5. 技术栈、运行与交付

Python 3.11+；LangChain / `langchain-openai` 负责工具声明和兼容模型接入；LangGraph 负责决策循环；Pydantic 负责输入、工具参数和返回结构校验；`uv` 锁定依赖；`pytest` 执行离线测试。模型默认 `deepseek-v4.1-flash-1017`，兼容接口地址和密钥只从本地 `.env` 或环境变量读取。

在仓库根目录执行：

~~~powershell
uv sync --extra dev
uv run --extra dev pytest -q
uv run knowledge-agent "正式员工申请年假需要提前多久？" --trace logs/manual-trace.jsonl
~~~

真实模型运行前，需要按 `.env.example` 在本机配置 `DASHSCOPE_API_KEY` 和 `DASHSCOPE_BASE_URL`。`logs/` 与 `.env` 被 Git 忽略。`README.md` 提供安装与评审入口；`data/` 存放合成资料和场景；`examples/` 存放 20 组输入与输出、其中 19 份 Trace（S19 空问题在模型调用前被拒绝）；`docs/01` 至 `docs/05` 分别记录需求、方案、评估、AI 使用与复盘。

保存的一轮全场景评估中，19 个有效输入由真实模型处理，S19 空问题在模型调用前被拒绝；20 个场景的最终状态均与预期一致，82 项离线测试通过。详见 `docs/03-evaluation.md`。这些结果只证明当前合成资料与场景下的运行表现。新问题、真实企业知识库和复杂多条款结论仍需更多评估；模型生成内容也可能出现与问题无关的补充说明，应继续人工审阅。
