# AI 辅助使用说明

## 使用范围与责任

本项目的开发助手使用 Codex。Codex 协助整理需求、设计最小实现、编写 Python 代码和文档、生成合成资料与测试场景、运行测试、分析真实 Trace，并根据观察到的问题修订实现。运行时 Agent 使用 deepseek-v4.1-flash-1017 选择工具动作和形成回答；这与参与开发的 Codex 是两个不同角色。

用户本人选择企业知识问答题目，明确要求使用 Python 与 LangChain/LangGraph，规定模块逐项验收、真实模型驱动的工具循环、错误状态、Trace 和 GitHub 交付范围；用户提供了模型接口与凭据，并在每个模块验收后决定是否继续。资料和场景均为合成内容，不来自真实企业内部文件。

开发中的代码、测试和文档主要由 Codex 编写。这里不把 AI 生成内容冒称为用户手写代码，也不声称用户已完成尚未发生的个人代码审查。候选人在正式提交前仍应亲自审阅代码、示例输出和仓库权限，并补充本人实际做过的修改。

## 关键人工判断与 AI 修改

| 事项 | 来源与处理 |
| --- | --- |
| 项目范围 | 用户要求先完成单 Agent 核心链路，避免多 Agent、前端和部署等非必要内容 |
| 技术选型 | 用户指定 LangChain/LangGraph；Codex用 LangGraph StateGraph 接入本地检索工具 |
| 知识材料 | Codex编写 10 份合成资料、20 个验收场景；用户确认样本规模可用于本阶段验收 |
| 模型配置 | 用户提供阿里云兼容接口、模型名称和 API Key；实际密钥只写在本地被 Git 忽略的 .env |
| 动态决策 | 首次真实运行只返回普通文本；Codex根据实际结果增加工具调用约束，随后记录真实模型工具路径 |
| 资料不足 | S03 曾反复检索至上限；Codex根据 Trace 调整通用停止提示，复跑后返回 insufficient_evidence |
| 引用核验 | Codex增加已读取文档、段落与原文子串校验；无效引用会返回模型修正 |
| 适用范围 | S12 首次误报 completed；Codex根据实际输出补充通用澄清规则，复跑后为 needs_clarification |

上述提示修改是根据实际失败记录做的工程调整。程序没有按场景 ID、预设答案或固定重试表决定模型下一动作；模型仍须观察工具结果后自行选择动作。

## 验证与限制

当前运行 82 项测试，覆盖检索、工具参数及返回验证、Agent 循环、错误与上限、引用核验、20 组保存材料的一致性。20 个合成场景中有 19 个有效输入调用真实模型，S19 空问题在调用前被拒绝；S06 的持续工具故障与 S09 的首轮空结果由受控测试后端提供，不能视为真实工具稳定性或召回率的证明。保存的 Trace 记录动作、参数、实际结果和后续动作，不包含模型内部思维。

完成状态的自动校验只能证明引句来自实际读取的原文，不能证明引文在语义上充分支持每一句回答。docs/03-evaluation.md 记录了本轮人工核对和局限；这些样本的一次通过不代表真实企业资料上的泛化准确率。

## 凭据与隐私

真实 API Key 不写入代码、示例、文档或测试。仓库仅保留 .env.example，真实 .env 被 .gitignore 排除。示例中的制度和产品内容均为合成资料。提交前应再次检查 Git 跟踪文件，确认没有密钥或个人隐私数据。
