# 开发复盘

## 目标与已完成内容

目标是交付一个可运行、可验证、工程结构清晰的企业知识问答 Agent。当前实现包含合成知识库、搜索与原文读取工具、LangGraph 模型决策循环、工具及引用校验、步数和调用次数上限、CLI、真实运行 Trace、测试与评估材料。全部 20 个合成场景的保存结果与预期状态一致，82 项测试通过。

## 最难的问题与处理

1. **让模型真正调用工具。** 首次接入真实模型时，它返回普通文本而未调用工具。根据接口支持情况设置每轮必须返回一个工具调用，并关闭并行调用；随后通过真实 Trace 检查模型是否继续依据工具结果行动。
2. **区分资料不足和无效重复检索。** 住宿补贴问题在资料库中没有答案，模型最初反复改写检索词直到上限。根据失败 Trace 调整通用决策提示后，模型在两次合理检索均无结果时说明缺口，返回 insufficient_evidence。
3. **避免“看起来有引用”的错误成功。** 完成提案现在必须引用本轮成功读取的文档、实际段落和连续原文；引用错误会作为结构化观察返回模型。准确的原文子串仍不等于语义支持，评估中继续人工核对关键结论。
4. **区分列举规则和确定适用规则。** S12 首次列出正式员工与实习生的不同期限，却误标 completed。增加通用的适用范围澄清提示后，模型请求确认身份并返回 needs_clarification。
5. **让输入错误优先暴露。** CLI 原先先检查模型配置，空问题在无密钥时会被配置错误掩盖。改为先验证问题与执行上限，再初始化模型。

## 学习与权衡

- Agent 的关键证据是“动作—实际工具结果—下一动作”的运行记录。测试替身可验证程序流程，真实模型 Trace 才能展示模型在具体观察下的选择。
- 搜索命中只是候选证据；读取原文、核对适用范围和明确状态是回答前的必要步骤。
- 将模型决策、工具执行、程序控制和引用校验分开，使失败原因可定位，同时保持单图、两个主要节点的简单结构。
- 小规模合成资料足以验证流程边界，但不足以估计真实企业知识库的召回率或准确率。因此本阶段未增加向量数据库、复杂 Runtime、多 Agent 或前端。

## 当前限制与下一步

自动引用核验只检查原文子串，复杂结论的语义支持仍需人工审阅。20 个合成场景是一次运行的验收材料；后续可在真实授权资料和更多问法上复测，发现检索漏召回时再决定是否升级检索方案。

正式提交前，候选人还需亲自复核项目、补充本人实际修改记录，并确认 GitHub 仓库权限、URL、最终 commit SHA 和密钥隔离。本文件不把这些尚未完成的外部提交步骤写成已完成。

本机项目目录的所有者与当前用户不同，Git 报出 dubious ownership。本轮只对单条 Git 命令指定该项目为 safe.directory，没有修改全局安全配置。后续在本机执行提交或推送前，应由用户确认仓库路径并处理该提示。
